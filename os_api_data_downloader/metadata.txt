description=Get OS NGD and OS MasterMap features, OS Places addresses and OS downloads for just your area - clipped to the map view, a drawn window or a polygon.
about=Created by CJM.
    One search box finds addresses (address, postcode or UPRN) and places (OS NGD Named Areas) and zooms to them. Choose an area of interest - the map view, a window (rectangle) or polygon drawn on the map, selected polygons, or a named area from the search - then:
    OS NGD: download any OS NGD API - Features feature types (buildings, land, roads, water…) for the area only.
    OS MasterMap: download OS MasterMap Topography Layer, Highways and other OS Features API (WFS) feature types for the area only, including annual snapshots.
    OS Addressing: every OS Places address in the area, chosen by classification (Residential, Commercial, Education…), as one layer or a layer per classification.
    OS Data Packages: OS OpenData products and your premium / PSGA data packages from the OS Downloads API, as 100 km tiles covering your area or for GB.
    NGD Data Linkages: tick OS NGD feature types and the links between them (Building to Site, Road Link to Road Node, Street by USRN, addresses by UPRN...) in a tree and download them already joined - link tables, joined copies and QGIS relations - with linked features outside the area fetched by ID.
    Find an NGD Feature Type: search what an OS NGD feature is described as (e.g. 'bridge') to find its feature type, grouped as polygons, lines then points, and download it straight away.
    Everything can be clipped to the area (cut at the edge, or keep whole features that touch it), saved to a GeoPackage and added to the map. Filter NGD and MasterMap features on their attributes, like the OS Data Hub. Cost estimates, a confirmation threshold and a transaction cap for every API download.

In filters, separate values with ; when one contains a comma. Fixed: the Postcode profile showed 0 addresses for every postcode - OS serves postcode units without an osid, so they are now keyed on the postcode itself.
    2.9.0 NGD Data Linkages: eight new 'Show off OS NGD' quick picks - Site address mix, Housing stock profile, Street profile (USRN), Postcode profile, Solar and roof potential, Green and sealed land, Site access and network, Community facilities - each with the residential / commercial / mixed-use address counts and percentages and a 'Character' column to colour the map by. The existing nine question picks stay below them. Fixed: answer columns reached through a link keyed on something other than the feature's ID (a Street's USRN, a postcode) came out empty.
    2.8.5 NGD Data Linkages: spatial links are now off by default - quick picks no longer switch them on. Site answers (Site understanding, Education, Asset management) now get their addresses through OS's own cross-references (Site <- Building -> address), so addresses and the residential / commercial mix come through without spatial links; 'Addresses inside, by location' is filled only when spatial links are ticked. The link colour key is now always shown under the tree and readable in light and dark themes. Links checked against the OS NGD relationship guidance: RAMI features read their Network Reference tables (filtered to Road Link / Road Node), Road Node -> Road Track or Path, Site -> main Building, and Site Access Location -> Path Node for entrances on the path network.
    2.8.4 NGD Data Linkages: fixed downloads taking 10+ minutes in 'fetching linked features'. A filtered feature type (e.g. Sites narrowed to schools) is no longer fetched by ID - the missing links were to the ordinary sites the filter leaves out on purpose, and OS's server fails (500) on those searches. When OS fails on ID searches for a feature type, the plugin now splits the batch a few times and then gives up on that type after four failures with no success, instead of retrying every batch (each failure could take a minute). Cancelling during the download now keeps and links everything downloaded so far instead of saving nothing.
    2.8.3 Fixed: HTTP 400 'not supported enumeration values' when a ticked value contains an apostrophe (e.g. Children's Nursery, Children's Centre in the Education quick pick, or in any attribute filter) - OS's API rejects the standard doubled quote, so such values are now matched with LIKE and a one-character wildcard (Children_s Nursery).
    2.8.2 NGD Data Linkages: quicker on small areas - a map view or drawn window is sent to OS as a plain bounding box (no extra shape filter for the server to test), the addresses are read at the same time as the OS NGD features rather than after them, and one-by-one address lookups are capped at 60; the status line now shows where the time went (counting, downloading, fetching linked features, writing, linking, building the answer) as well as the transactions. Also: when OS's data doesn't include a Building's cross-references (its addresses, parts or sites) - as can happen through the API - they are now worked out from location instead (an address inside the building, a part inside it, the building inside a site), so the Quick pick answers still have their addresses, address mix, floor area per address, building parts and site details; the status line says which links were worked out this way. A clear note if OS Places returns no addresses for the area.
    2.8.1 NGD Data Linkages - faster, especially with everything ticked: pressing Download goes straight to a quick count (one request per feature type, whose page is reused by the download) instead of the full count with its extra probe requests; big feature types are read in growing waves of pages; layers are opened in the background so QGIS no longer freezes for several seconds at the end; all link tables are written through one open file; 10 requests in flight. Fixed: a guessed field name could pick another feature type's reference (e.g. Building Part IDs taken for Building IDs), sending thousands of pointless lookups; a feature type whose IDs aren't found within 500 m is no longer searched for again at 5 km. The rich answer layer (densities, floor areas, composition) is made only with 'Show me: Just the answer'; in that view the link tables stay in the file rather than being loaded into QGIS.
